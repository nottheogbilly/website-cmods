CMods Lua API Docs

Complete reference for creating Lua scripts, custom parts, HUD buttons, and ImGui windows for BlocksC.

Platform Support: On Linux, full Lua scripting, ImGui windows, HUD buttons, and asset overrides are supported. On Windows, only asset overrides and world/parts.json are supported.

1. How Mods Run

CMods loads .zip mods from /mods/. On every launch, it builds a clean staging tree (.cmods/staging/) without ever modifying your original blocksC executable:

  1. Overlays mod files onto a hardlinked copy of the game assets.
  2. Merges world/parts.json part definitions into the staged scene (assets/default.json).
  3. Patches the staged executable to run Lua at boot and registers C bindings (destroy, clonepart, _uiBegin, _uiEnd, _uiText, _uiButton).
  4. Appends the mod runtime and all mod scripts to the staged assets/corescripts/main.lua.

Each mod's scripts/init.lua executes inside a pcall at boot. If a mod errors, CMods logs [CMods] mod '' failed: … and the game continues running.

2. Mod Package Structure & Manifest

Package your mod as a .zip file in the mods/ folder:

MyMod.zip
├── mod.json            # Required manifest
├── scripts/
│   ├── init.lua        # Entry point (runs at boot)
│   └── helpers.lua     # Optional modules loaded via mod.require()
├── assets/             # Hardlinked into staging; text files readable via mod.asset()
├── world/parts.json    # Optional parts spawned into the scene at boot
└── hud.json            # Optional buttons added to the CMods HUD window

mod.json Manifest

{
  "id": "hello-mod",
  "name": "Hello Mod",
  "version": "1.0.0",
  "author": "you",
  "description": "Example CMods mod",
  "order": 100
}
Field Type Default Notes
id string zip name Sanitized identifier used by enable/disable
name string id Display name shown in the CMods window
version string "?" Mod version string
author string "" Author name
description string "" Short description
order number 100 Lower numbers load first

You can also override load order or disable mods globally in /cmods.json:

{
  "disabled": ["old-mod"],
  "order": ["my-mod", "other-mod"]
}

3. The mod Table (Modules & Assets)

Passed as the second argument to init.lua and any module loaded via mod.require.

Member Returns / Type Description
mod.id / mod.name / mod.version string Metadata from your mod.json
mod.dir string Staged path ("assets/corescripts/mods//")
mod.asset(name) string | nil Reads a text file from assets/ (max 64 KB per file, 512 KB total)
mod.assetNames() table Sorted list of bundled text asset paths
mod.require(name) any Loads and caches scripts/.lua (e.g. mod.require("ui/widget"))
mod.hudOnClick(name, fn) nil Binds a click callback to a button ID defined in hud.json
mod.ui table Persistent ImGui window API (window, text, button)

Example: Splitting Code into Modules & Reading Assets

-- scripts/helpers.lua
local M = {}
function M.greet(modName)
    return "[" .. modName .. "] Ready!"
end
return M
-- scripts/init.lua
local helpers = mod.require("helpers")
print(helpers.greet(mod.name))

-- Read bundled text file from assets/notes.txt
local notes = mod.asset("notes.txt")
if notes then
    print("Loaded asset: " .. notes)
end

4. Scene Parts: world/parts.json & obj

To spawn new parts at game start, declare them in world/parts.json. They are merged into the scene before Lua boots.

[
  {
    "name": "TargetBlock",
    "shape": "Box",
    "position": [-7.0, 6.0, -10.0],
    "rotation": [0.0, 0.0, 0.0],
    "scale": [1.5, 1.5, 1.5],
    "color": [0.85, 0.15, 0.15],
    "anchored": true,
    "transparency": 1.0,
    "reflectiveness": 0.0
  }
]

Querying, Cloning & Destroying Parts via obj

obj is a read-only boot snapshot of the workspace. Lookups are case-insensitive.

-- List all unique part names in the scene
local parts = obj:list()
print("Total unique parts: " .. #parts)

-- Case-insensitive lookup (both lines find the same part)
local p1 = obj.targetblock
local p2 = obj.get("TARGETBLOCK")

-- Clone a part (creates "TargetBlockClone", "TargetBlockClone2", etc.)
if obj.John then
    local copy = obj.John:Clone()
    if copy then
        print("Cloned as: " .. copy.name)
        -- Re-read from obj if you need the live wrapper reference
        local ref = obj[copy.name]
    end
end

-- Destroy a part from the running engine
if obj.TargetBlock and obj.TargetBlock:Destroy() then
    print("TargetBlock removed!")
end

5. Persistent ImGui Windows (ui API)

Register persistent windows at boot using mod.ui.window (or global ui.window). The draw function runs once per frame inside a pcall.

mod.ui.window(id, title, drawFn)

Registers a persistent window wrapped in ImGui::Begin(title) / ImGui::End().

ui.text(str) & ui.button(label)

Call these only inside your drawFn. ui.button returns true on the frame it is clicked.

Example: Interactive Part Spawner Window

-- scripts/init.lua
local cloneCount = 0
local statusMsg = "Idle"

mod.ui.window("spawner-ui", "Part Spawner", function()
    ui.text("Unique parts in scene: " .. #obj:list())
    ui.text("Clones created: " .. cloneCount)
    ui.text("Status: " .. statusMsg)

    if ui.button("Clone Green Part") then
        if obj.green then
            local copy = obj.green:Clone()
            if copy then
                cloneCount = cloneCount + 1
                statusMsg = "Created " .. copy.name
            else
                statusMsg = "Clone failed (engine part capacity full)"
            end
        else
            statusMsg = "Part 'green' not found"
        end
    end

    if ui.button("Destroy Red Part") then
        if obj.red and obj.red:Destroy() then
            statusMsg = "Destroyed red part"
        else
            statusMsg = "Red part already gone"
        end
    end
end)

6. Built-in HUD Buttons (hud.json)

If you just want quick buttons inside the built-in CMods mod-list window without creating a separate window, declare them in hud.json and bind handlers at boot:

// hud.json
{
  "buttons": [
    { "id": "poke", "label": "Poke Demo!" },
    { "id": "clone", "label": "Clone John!" }
  ]
}
-- scripts/init.lua
mod.hudOnClick("poke", function()
    print("[my-mod] Poked! Global button ID: " .. mod.hudButtons["poke"])
end)

mod.hudOnClick("clone", function()
    local copy = obj.John and obj.John:Clone()
    if copy then
        print("[my-mod] Cloned -> " .. copy.name)
    end
end)

7. CLI Commands

Manage mods and launch the game from your terminal:

cmods run                 # Launch the game with enabled mods (default)
cmods stage               # Build .cmods/staging/ without launching
cmods list                # List discovered mods and enabled/disabled status
cmods enable          # Enable a mod
cmods disable         # Disable a mod
cmods new  --package  # Scaffold a new mod folder and zip it into mods/
cmods --vanilla           # Launch without any mods

8. Important Gotchas

  • Keep draw functions fast: mod.ui.window callbacks execute every frame; heavy loops inside them will drop game FPS.
  • Fix UI errors quickly: If a ui.window draw function throws a Lua error, it prints [CMods] ui '' failed: … every single frame.
  • obj is a snapshot: Calling part:Clone() updates obj for future lookups, but variables referencing obj from before the clone won't automatically refresh.
  • Finite clone headroom: The engine's part vector pre-allocates slots to the next power of two at boot (e.g., 18 parts → 32 slots = 14 clones max). Clone() returns nil once full.
  • Line-buffered logs: When redirecting stdout to a file, run with stdbuf -oL ./cmods so print() output appears immediately.
